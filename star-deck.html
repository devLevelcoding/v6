Situation, overall V1 → V2 → V3

Two real production apps covered ~29% of a senior-Go curriculum.
The other 71% became 100 standalone projects — then five of its ideas hardened five real services.

Situation

An internal audit (StatusGo.md) scored two shipped apps against a 100-topic senior-Go plan — concurrency, testing, observability, distributed systems and security depth almost entirely untouched. Separately, featureGo.md pitched five V5 services on 6–30× wins, every figure "indicative, not measured."

Task

V3: close the curriculum gap with real, running software — one project per day, verified against real inputs. V5: turn "indicative" into "measured" — one Go concept per sprint, applied to GoGate / GoStream / GoRender / GoFlare / GoSnow with a passing benchmark or test.

Action

Sections 01–09: 100 concepts, each its own STAR, capped by a live microservices capstone. Sections 10–14: 19 CoverGo concepts in one session, each landing in real code with a measurement.

Result

100/100 shipped and verified. 19/19 CoverGo concepts landed — GoGate proxy −58% B/op, GoStream broadcast 0 allocs/op, ws unmask 7.8×, a real panic-deadlock fixed, all 5 repos green.

Beyond the 100 days this session · V3

V2 was one workspace. V3 makes every concept stand on its own.

Situation

All 100 V2 projects shared one go.work workspace — convenient to build together, but no single project could be handed off or built alone.

Task

Copy V2 into V3 as fully standalone modules, then audit and refactor the largest, riskiest files for real maintainability.

Action
  • De-workspaced all 100 projects; vendored the one real cross-project dependency (Day 12's circuit breaker) where needed.
  • Added a Redis container for the 4 projects that are real Redis clients — no DB container, since nothing else in 100 projects touches Postgres, MySQL, or Mongo.
  • Refactored the 8 largest files (649 → 185 lines, max) by splitting on responsibility and deduplicating repeated logic.
  • Fixed a real concurrency bug found along the way: a package-level global var shared across Generator instances.

Sections 10–14 · what CoverGo actually was featureGo.md → measured

featureGo.md said "benchmark the one you build first." This session built the benchmarks.

Situation

The featureGo.md audit ended with a warning: the 6–30× multipliers "come from workload shape crossed with runtime characteristics, not measurements — treat them as which order of magnitude, then benchmark."

Task

Turn "indicative" into "measured" for the parts measurable on this machine, across GoGate / GoStream / GoRender / GoFlare / GoSnow — and mark the rest honestly.

Action
  • 19 concepts (S0 → P9), each with a testing.B or a test; -count=6 baselines committed to bench/latest.txt.
  • Two latent bugs fixed as side effects: the cache panic-deadlock (U17), a half-written artifact left downloadable on failure (U19).
  • golang.org/x/sync adopted in GoFlare / GoRender / GoGate — a deliberate, documented break from stdlib-only.
  • 23 tasks needing cgo (DuckDB), gRPC codegen or a linux CI stay todo with a comment naming the blocker.
